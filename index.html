3. What We See — Gateway-Exposed Signals

The Gateway Explained

Modern vehicles don't put every ECU on the OBD-II diagnostic bus (pins 6/14). Instead, a central gateway bridges internal networks (PT-CAN, K-CAN, F-CAN, etc.) and selectively exposes signals to the diagnostic port. We capture and decode what the gateway chooses to expose — not manufacturer-internal data, but the signals that matter for diagnostics: wheel speeds, steering angle, yaw rate, battery voltage, door status, brake pressure, HVAC, cluster warnings, and more. Coverage varies by manufacturer, model, and year; we discover it per vehicle.

What This Enables

From gateway-exposed signals we detect and diagnose wheel bearing/hub faults, door latch failures, battery/alternator/wiring issues, ESC false activation, steering sensor drift, and yaw/lateral acceleration sensor zero errors.

Intelligence Layer

We cross-reference DTCs with live signal behaviour, compare left/right and front/rear symmetry, detect sub-threshold anomalies (misfires below DTC threshold, sensor drift before fault codes), and build per-vehicle baselines for trend monitoring and early warning.

4. K-Line Direct ECU Access (When Gateway Blocks)

K-Line Address Reference (Common Defaults)

TargetAddressProtocolUse Case
Engine ECU0x10ISO 14230-4 (ATSP 4)When gateway blocks UDS
Gateway0x19ISO 14230-4 (ATSP 4)Direct gateway diagnostics
ABS0x03ISO 14230-4Gateway-independent

Transmission0x02ISO 14230-4TCM direct
HVAC0x08ISO 14230-4Body diagnostics

Vehicle-dependent: K-Line must be wired to pin 7 on target ECU. Not all manufacturers/vehicles support all addresses. Common on VW Group, BMW, and many European platforms.

Arbitrary addressing: Any 8-bit K-Line address (0x00–0xFF) reachable via ATSH — the table above shows common defaults only.

ISO 9141-2 support: 5 baud init (ATSI/ATSP 3) for older Asian, European, Chrysler ECUs that predate KWP2000.

Custom K-Line timing: STIFI (custom fast init), STITW (per-timing-parameter config), STIIAP (init address parity), STIP/STIP1X (communication parity & P1 max) — enables access to ECUs violating ISO timing specs.

Gateway-Blocked ECUs: K-Line ISO-TP direct to Engine (0x10) and Gateway (0x19) when CAN gateway blocks UDS — no bench removal required.

6. Advanced Capabilities

6.1 Security Access (UDS 0x27)

Security-access operations (ECU replacement, immobilizer sync, variant coding, adaptation writes) with written authorisation only. Platform-specific — requires verified seed/key algorithm. Not a universal unlock.

6.2 Gateway Wake Strategies

  • K-Line 0x10/0x19 with 5 baud init or fast init
  • Custom fast init (STIFI) for difficult ECUs
  • USB host detect sleep/wake (EX rev 2.5+)

6.3 J1939 (Commercial Vehicles)

  • PGN filtering (STFPGA) — multi-PGN simultaneous monitor
  • Target address filtering (specific ECU, broadcast FF, or all)
  • TP.CM / TP.DT multi-frame reassembly (BAM + RTS/CTS)
  • J1939-73 diagnostics (DM1/DM2 faults)
  • ACK frame processing
  • ATJ S/ATJ E — little-endian PGN request control

6.4 CAN FD & Addressing

  • CAN FD capture (OBDLink EX) — DLC up to 64 bytes on diagnostic bus
  • Addressing formats: Normal, Extended, Mixed, Normal Fixed (STCAF 0–3)
  • ISO 15765-4 preset formats (STP 33–42) — pre-configured for OEM variants
  • Custom flow control ID pairs (STCFCPA 11-bit, STFFCA 29-bit)
  • Extended addressing: STCAF 1,xx + ATTA yy (gateway-separated ECUs)
  • Mixed addressing: STCAF 2,xx (same extended addr for Tx/Rx)

6.5 Periodic Transmission & Arbitrary Transmit

  • STPPMA interval, header, data — add periodic message (returns handle)
  • STPPMD handle — delete specific periodic message
  • STPPMC — clear all periodic messages
  • STPX — arbitrary frame transmit: custom header, data (or length + DATA> prompt), timeout, response count, extended address, flags — up to 2KB, any protocol
    • Use cases: ECU simulation, actuator testing, custom service routines, parameter writes (with authorisation)

6.6 Non-Standard & Custom Protocols

  • Custom CAN protocol: STCSP — user-defined CAN parameters
  • Custom CAN baud: STCBR / STCBA — non-standard bit rates
  • Register-level timing: STCTR — direct CAN timing register access
  • ISO 15765-4 presets: STP 33–42 — pre-configured addressing format variants
  • Adaptive timing: ATAT 1 (normal) / ATAT 2 (aggressive) — auto-tunes inter-frame timeout per vehicle
